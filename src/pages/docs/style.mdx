# Render style

`style`은 **무엇을 그리는지가 아니라 어떻게 그리는지**를 정합니다.

같은 문서가 블로그 글, 강의 슬라이드, 논문 도판으로 각각 어울리게 나와야 합니다. 그러자고 문서를 복제해 색을 고치는 것은 답이 아닙니다.

```json
{ "style": { "preset": "sketch", "seed": "bellman-ford", "roughness": 1.2 } }
```

| preset | 내용 |
| --- | --- |
| `clean` | 지금까지의 렌더. 기본값이며 **출력이 바이트 단위로 동일합니다** |
| `sketch` | 결정적 지터. `rect`·`circle`·`polygon`은 흔들린 `path`가 되고 `line`은 끝점만 움직입니다 |
| `mono` | luma 기준 그레이스케일. 인쇄·논문용 |

## 구현 위치가 설계입니다

`buildScene` 이후, adapter 이전의 **순수 Scene → Scene 변환**입니다. 이 자리라서 가능한 것이 셋입니다.

- **요소 빌더 11종을 건드리지 않습니다.** preset은 원이 무엇인지에 대한 규칙이 아니라 그리는 방식에 대한 규칙입니다.
- **adapter 4종과 GIF가 전부 공짜로 따라옵니다.**
- **노드의 종류를 바꿔도 안전합니다.** `key`만 보존하면 DOM patcher와 React 재조정이 그대로 동작하고, 그 아래로는 아무도 rect였는지 신경 쓰지 않습니다.

## 결정성 — 시각을 시드에 넣지 않습니다

지터는 난수처럼 보이되 난수여서는 안 됩니다. GIF를 두 번 구우면 같은 파일이어야 하고, seek해서 온 프레임이 재생해서 온 프레임과 같아야 합니다.

시드는 `hash(style.seed ?? doc.id, node.key, node.kind)`이고 PRNG는 mulberry32입니다.

**시각 `t`는 시드에 들어가지 않습니다.** 넣으면 스케치가 살아 있어 보이게 만드는 가장 쉬운 방법이자 **화면을 끓게 만드는 가장 확실한 방법**이 됩니다 — 매 프레임 선이 다시 섞여 그림 전체가 어른거립니다. 무대를 가로질러 움직이는 요소는 자기 지터를 그대로 갖고 다닙니다.

## 손대지 않는 것

- **`text`와 `image`**: 글자를 흔들면 편안해지는 게 아니라 안 읽힙니다.
- **`path`**: 임의의 path data를 다시 그리려면 완전한 파서가 필요합니다.
- **spotlight scrim과 mask**: 가장자리가 흔들리면 무대 둘레에 밝은 틈이 생깁니다.
- **`mono`에서 `var(--cloth-*)` 토큰**: 값을 정하는 것은 페이지이고, 이미 중요한 의미에서 단색입니다.

`mono`는 화살촉(marker)까지 회색조로 바꾸고 **그 marker에 새 id를 줍니다.** marker id는 문서 전역이고 색이 id에 박혀 있어 지금까지는 같은 id면 내용도 같았는데, preset이 그 전제를 깹니다 — 회색 marker와 컬러 marker가 같은 id를 주장하면 `url(#…)`은 페이지에 먼저 로드된 쪽으로 해석됩니다.

노드 수가 임계값(400)을 넘으면 `sketch`는 **`clean`으로 강등됩니다.** 그만큼 빽빽한 그림에서 손그림 선은 멋이 아니라 잡음이고, path 데이터도 두 배로 늘어납니다.

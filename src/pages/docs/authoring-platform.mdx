# 확장형 작성 환경

Clotho의 작성 기능은 JSON Schema를 중심으로 서로 연결됩니다. 핵심 표현과 실행 규칙은 runtime에 포함하고, host별 입출력과 추가 검사는 plugin으로 확장합니다. 따라서 문서를 특정 editor나 저장소에 종속시키지 않고도 작성, 검사, 재생과 배포 단계를 같은 데이터로 이어갈 수 있습니다.

## 전체 작성 흐름

1. `defineAnimation` 또는 template으로 문서를 만듭니다.
2. 외부 `data`를 binding하여 반복되는 값을 채웁니다.
3. constraint와 responsive variant로 stage 배치를 계산합니다.
4. linter와 visual regression으로 결과를 검사합니다.
5. React, DOM, SVG와 GIF adapter에서 같은 문서를 재생합니다.

[Gallery의 장애 대응 흐름](/#gallery)은 이 과정에서 함께 쓰이는 기능을 하나의 실제 문서로 보여줍니다.

## Plugin system

`definePlugin`으로 manifest와 hook을 선언하고 `createPluginRegistry`에 등록합니다. `runPluginPipeline`은 `parse → normalize → compile → validate` 순서를 적용하며, `exportWithPlugins`는 export hook이 만든 artifact를 모읍니다.

```ts
import { createPluginRegistry, definePlugin, runPluginPipeline } from "@kokoa/clotho";

const policy = definePlugin({
  manifest: {
    id: "company-policy",
    version: "1.0.0",
    capabilities: ["validate"],
  },
  validate(document) {
    return document.title ? [] : [{ path: ["title"], message: "제목을 입력하세요." }];
  },
});

const registry = createPluginRegistry([policy]);
const result = runPluginPipeline(input, { registry });
```

Plugin은 JSON 값을 복제해 전달받으며 실행 순서와 결과가 trace에 남습니다. core의 schema, geometry, timeline과 scene 계산을 대체하는 용도가 아니라 host 정책, import/export와 추가 검사를 연결하는 경계입니다.

## Constraint layout

`layout.constraints`는 요소의 위치와 간격 관계를 선언합니다. `align`, `distribute`, `gap`, `pin`, `center` 같은 관계를 compile 단계에서 좌표로 바꾸므로 template이나 binding으로 요소 수가 달라져도 규칙을 유지할 수 있습니다. 순환 참조와 존재하지 않는 ID는 검증 단계에서 오류로 보고됩니다.

## Linked annotation

문구 안의 annotation token은 요소 ID와 연결할 수 있습니다. runtime은 현재 문구를 token으로 분리하고 연결 정보를 보존하므로 host가 hover, focus와 click 동작을 추가할 수 있습니다. 설명 문장과 장면의 대상을 별도 좌표로 중복 관리하지 않아도 됩니다.

## Template과 parameter

`defineTemplate`은 string, number, boolean, enum, array와 object parameter를 선언하고 문서 factory를 연결합니다. `instantiateTemplateReference`는 기본값을 채우고 입력을 검사한 뒤 완전한 `AnimationDocument`를 반환합니다.

```ts
const traversal = defineTemplate({
  id: "array-traversal",
  parameters: {
    values: { type: "array", default: [4, 2, 7] },
    interval: { type: "number", default: 400, min: 100 },
  },
  create: ({ values, interval }) => ({ /* Clotho document */ }),
});
```

## Interactive checkpoint

`checkpoints`는 지정한 시간에서 재생을 멈추고 사용자의 응답을 기다립니다. choice, text와 number 입력을 지원하며 predicate로 정답 또는 통과 조건을 구성합니다. checkpoint가 없는 기존 문서는 이전과 동일하게 연속 재생됩니다.

## Data binding

문서의 `data`는 JSON 값이며, 각 요소의 `bindings`는 JSON Pointer로 값을 읽어 허용된 속성에 연결합니다. `format`을 사용해 숫자나 문구를 표시용 값으로 바꿀 수 있습니다. `compileDataBindings` 결과는 새 문서이므로 원본 작성 데이터는 바뀌지 않습니다.

```json
{
  "data": { "incident": { "severity": "SEV-1" } },
  "elements": [{
    "type": "text",
    "id": "severity",
    "content": "상태",
    "bindings": [{ "property": "content", "pointer": "/incident/severity" }]
  }]
}
```

## Branching story

분기는 한 문서 내부의 임의 jump가 아니라 여러 완전한 Clotho 문서를 `StoryManifest`로 연결합니다. `createStorySession`은 선택, 뒤로 가기와 초기화를 관리하고 `storyDeepLink`는 특정 node로 연결할 URL을 만듭니다. 각 node가 독립 문서이므로 SVG/GIF export와 cache도 그대로 사용할 수 있습니다.

## Responsive stage

`responsive.variants`는 `minWidth`, `maxWidth`, canvas 변경, 요소 override와 chapter 위치를 선언합니다. `compileResponsiveStage`는 viewport에 맞는 문서를 만들며 React와 DOM player는 container 폭의 변화를 감지해 현재 시간을 유지한 채 variant를 바꿉니다.

## 큰 scene의 성능

`compileSceneDependencyPlan`은 track, keyframe과 요소 참조 관계를 미리 계산합니다. `createPreparedSceneBuilder`는 이 계획과 제한된 frame cache를 재사용하고, `cullDocumentToViewport`는 화면 밖 요소를 제외합니다. 최적화 전후의 scene 결과가 같은지 먼저 검사한 뒤 사용해야 합니다.

## Linter와 자동 수정

`lintDocument`는 `correctness`, `accessibility`, `recommended` preset을 제공합니다. 사용하지 않는 asset, 정렬되지 않은 keyframe과 빈 번역처럼 의미가 명확한 항목만 `autofixDocument`가 수정합니다. 겹치는 배치, 작은 요소, text overflow처럼 판단이 필요한 항목은 finding만 반환합니다.

```bash
clotho lint animation.json
clotho lint animation.json --fix
```

## Visual regression

대표 viewport와 시간을 정하고 SVG 결과의 hash를 baseline으로 보관합니다. `bun run visual:check`는 현재 gallery 문서가 baseline과 같은지 확인하고 차이가 있으면 CI artifact를 남깁니다. 의도한 변화임을 눈으로 확인한 뒤에만 `bun run visual:update`로 기준을 갱신합니다.

## Editor에서 확인하기

Clotho Editor의 개발용 plugin panel에서 data binding, story graph, responsive inspector, 성능 profiler, linter와 visual regression을 확인할 수 있습니다. 저장되는 값은 Clotho JSON이고 inspector 상태는 문서에 섞이지 않습니다.

# Camera

Camera는 **읽는 사람이 캔버스의 어느 부분을 보고 있는지**를 정합니다. 요소를 움직이는 것이 아니라 화면을 움직입니다.

Camera가 없던 시절, 큰 그래프를 설명하려면 두 가지 방법밖에 없었습니다. 전체를 작게 그려서 글씨가 안 보이게 하거나, 문서를 여러 개로 쪼개서 흐름을 끊거나. `camera`는 하나의 문서 안에서 전체를 보여준 뒤 필요한 곳으로 들어갔다가 다시 나오는 것을 가능하게 합니다.

왼쪽이 실제로 표현되는 화면이고, 오른쪽은 같은 시간의 캔버스 전체 위에 카메라가 잡고 있는 영역을 상자로 표시한 것입니다.

## 언제 쓰고, 언제 쓰지 말아야 하나

카메라는 **강조 수단이지 배치 수단이 아닙니다.** 화면을 움직이는 것은 읽는 사람에게 "지금 여기를 보라"고 말하는 가장 강한 방법이고, 그래서 극적입니다. 강한 도구가 다 그렇듯 자주 쓰면 효과가 사라지고, 남는 것은 멀미뿐입니다.

**쓸 만한 경우**

- 캔버스 전체를 다 보여주면 글씨가 읽히지 않을 만큼 그림이 큰 경우.
- 설명이 지금 한 부분에 대한 것이고, 나머지는 잠시 배경으로 물러나도 되는 경우.
- 움직이는 대상을 따라가야 하는 경우 — 이건 `focus`가 아니면 손으로 흉내내기 어렵습니다.
- 전체 → 부분 → 전체처럼, 이동 자체가 "확대한다"는 설명의 일부인 경우.

**쓰지 말아야 하는 경우**

- **요소를 배치하는 대신 쓰는 것.** 처음부터 잘 배치된 그림은 카메라가 필요 없습니다. 카메라로 이동하기 전에 캔버스 크기와 요소 위치를 먼저 고치세요.
- **chapter마다 한 번씩.** 카메라 이동이 장면 전환의 기본 동작이 되면 그것은 더 이상 강조가 아닙니다.
- **한 요소를 강조하려는 것.** 그 목적에는 `highlight`·`pulse`·spotlight가 있고, 화면을 움직이지 않으므로 맥락을 잃지 않습니다.
- **읽는 시간이 필요한 텍스트 위에서.** 글을 읽는 동안 화면이 움직이면 읽을 수 없습니다.

**분량의 감각**

한 문서에 focus 서너 개 정도가 대체로 상한입니다. 그보다 많다면 대개 두 가지 중 하나입니다 — 캔버스가 너무 크거나, 한 문서가 두 개의 설명을 담고 있거나. 이동 사이에는 화면이 멈춰 있는 시간을 충분히 두세요. 읽는 사람은 도착한 뒤에야 내용을 봅니다.

그리고 카메라를 쓴 문서는 **`prefers-reduced-motion`에서 이동이 전부 컷으로 바뀝니다.** 이동 과정에 설명을 싣지 말고, 도착한 화면만으로도 말이 되게 만드세요.

## 두 가지 작성 방식

`camera`는 최상위 필드이며 `tracks`, `focus`, `strokeScaling`으로 구성합니다. 둘은 함께 쓸 수 있습니다. **이미 시작된 focus가 있으면 그 focus가 이기고**, 없으면 `tracks`의 값이 쓰입니다. focus가 이동해 들어올 때는 그 순간 `tracks`가 가리키던 자리에서 출발하므로, 둘을 섞어도 화면이 튀지 않습니다.

### focus — 요소를 지정합니다

대부분의 경우 이쪽을 씁니다. 좌표와 배율 대신 **무엇을 보여줄지**를 적습니다.

```json
{
  "camera": {
    "focus": [
      { "time": 1200, "duration": 800, "elementIds": ["ingest"], "padding": 24 },
      { "time": 3200, "duration": 900, "elementIds": ["worker", "retry"], "padding": 22 }
    ]
  }
}
```

| 필드         | 설명                                                        |
| ------------ | ----------------------------------------------------------- |
| `time`       | 이동을 시작하는 시각 (ms)                                   |
| `duration`   | 이동에 걸리는 시간. 기본 600, `0`이면 컷                     |
| `elementIds` | 화면에 담을 요소들. 여러 개면 그 요소들을 모두 포함하는 영역 |
| `padding`    | 대상 주변 여백 (캔버스 단위). 기본 24                        |
| `maxZoom`    | 확대 상한. 기본 4                                            |
| `ease`       | 이동 곡선                                                    |

focus는 **매 프레임 실제 요소 위치를 다시 계산합니다.** 그래서 대상이 움직이면 카메라가 따라갑니다. 위 예시의 네 번째 구간이 그것입니다 — 빨간 packet이 이동하는 동안 카메라가 계속 그것을 담고 있습니다.

하나의 focus는 **다음 focus가 나오거나 문서가 끝날 때까지 유지됩니다.** 원래 자리로 돌아오려면 전체를 담는 focus를 하나 더 넣습니다.

`maxZoom`은 작은 요소 하나에 focus했을 때 화면이 그 요소로 가득 차 버리는 것을 막습니다.

### tracks — 값을 직접 적습니다

카메라 움직임 자체가 설명의 일부일 때 씁니다. 요소 track과 같은 keyframe 모델을 그대로 사용합니다.

```json
{
  "camera": {
    "tracks": [
      {
        "property": "zoom",
        "keyframes": [
          { "time": 0, "value": 1 },
          { "time": 2000, "value": 2.6, "ease": "easeInOut" }
        ]
      },
      { "property": "x", "keyframes": [{ "time": 0, "value": 400 }, { "time": 2000, "value": 140 }] },
      { "property": "y", "keyframes": [{ "time": 0, "value": 250 }, { "time": 2000, "value": 150 }] }
    ]
  }
}
```

`property`는 `zoom`, `x`, `y` 세 가지뿐이고 값은 항상 숫자입니다. `x`와 `y`는 **화면의 중심**이 놓일 캔버스 좌표이며, `zoom`은 배율입니다. 기본값은 캔버스 중심에 `zoom: 1`입니다.

좌표가 캔버스 단위이므로 반응형 stage가 크기를 바꿔도 카메라가 가리키는 곳은 그대로입니다.

## strokeScaling — 확대할 때 선 두께

```json
{ "camera": { "strokeScaling": "fixed" } }
```

| 값                 | 표현                                                                    |
| ------------------ | ----------------------------------------------------------------------- |
| `scale` (기본값)   | 광학 카메라와 같습니다. 확대하면 선도 함께 굵어집니다                    |
| `fixed`            | 배율로 나누어 선 두께를 일정하게 유지합니다. 조밀한 다이어그램에 좋습니다 |

`fixed`는 `vector-effect`가 아니라 계산된 숫자로 장면에 적용됩니다. 그래서 React, Vue, DOM, SVG 문자열과 resvg 기반 GIF 렌더러가 모두 같은 결과를 냅니다.

## 접근성 — 움직이는 화면과 reduced motion

움직이는 화면은 읽는 사람을 멀미하게 만드는 가장 확실한 방법입니다. 그래서 `prefers-reduced-motion`이 켜져 있으면 카메라는 **느려지는 것이 아니라 보간을 하지 않습니다.** 다음 keyframe에 도달할 때까지 이전 값을 유지하다가 한 번에 바뀝니다 — 이동이 컷으로 바뀝니다.

문서 쪽에서 따로 할 일은 없습니다. adapter가 자동으로 처리합니다.

## 코드에서 카메라 값 읽기

`computeCamera(document, time)`는 그 시각에 보이는 사각형과 그것을 만든 값을 함께 돌려줍니다. 위 예시의 오른쪽 상자가 이 함수의 결과입니다.

```ts
import { computeCamera } from "@kokoa/clotho";

// camera가 없는 문서에서는 null입니다.
const view = computeCamera(document, 3200);
// view.x, view.y, view.width, view.height — viewBox
// view.centerX, view.centerY, view.zoom   — 작성된 값
// view.issues                             — 해결되지 않은 focus
```

같은 시간에 대해 항상 같은 값을 돌려줍니다. seek, 정적 출력, GIF 프레임, editor의 scrub이 모두 같은 화면에 동의하는 이유입니다.

`elementIds`가 그 시각에 화면에 없는 요소를 가리키면 카메라는 직전 상태를 유지하고 `issues`에 `focus-unresolved`를 담습니다. 화면이 갑자기 이상한 곳으로 튀는 대신, 무엇이 잘못됐는지 알려줍니다.

## Adapter와 출력

카메라는 `Scene.viewBox` 하나로 나옵니다. `Scene`이 이미 가지고 있던 필드라서 **adapter는 아무것도 바뀌지 않았습니다.** React, Vue, DOM, SVG 문자열과 GIF 렌더러가 그 값을 그대로 통과시킵니다.

# 문서에 끼워 넣기

같은 문서를 블로그 글, 남의 페이지, 스크롤 기사, 발표 화면에 각각 올리는 방법입니다. 문서를 복제하지 않습니다.

## 마크다운 · MDX

```js
import { remarkClotho } from "@kokoa/clotho/mdx";
const plugins = [remarkClotho()];
```

````md
```clotho
{ "clothoVersion": 1, "id": "queue", "duration": 3000 }
```
````

빌드 시 문서를 **검증하고**(실패하면 빌드가 실패합니다) 포스터 프레임 SVG를 마크업에 인라인합니다. **JS 없이도 그림이 보이고**, 테마 토큰이 살아 있어 다크 모드를 따라갑니다.

```ts
import { hydrateClothoEmbeds } from "@kokoa/clotho/mdx";
hydrateClothoEmbeds(); // 뷰포트에 들어오는 것부터 player로 승격
```

프레임워크 컴포넌트가 아니라 **HTML**을 내보내므로 Astro · Next(MDX) · Docusaurus · Vitepress · 순수 마크다운이 모두 같은 경로를 탑니다.

## 웹 컴포넌트 (번들러 없이)

```html
<script type="module">
  import { defineClothoPlayer } from "@kokoa/clotho/element";
  defineClothoPlayer();
</script>

<clotho-player src="/animations/knapsack.json" theme="dark" autoplay loop></clotho-player>
```

문서를 인라인으로 넣으면 네트워크 요청도 사라집니다.

```html
<clotho-player>
  <script type="application/json">{ "clothoVersion": 1 }</script>
</clotho-player>
```

shadow root에 렌더하고 **스타일시트를 함께 들고 갑니다** — 남의 페이지에 얹힐 때 호스트 CSS와 충돌하지 않습니다. 테마 토큰(`--cloth-*`)은 CSS 변수라 경계를 통과하므로 호스트의 팔레트 오버라이드는 그대로 동작합니다.

`el.player`로 `seek`·`play`·`setSpeed`를 부를 수 있고 `clotho-ready` · `clotho-chapterchange` · `clotho-ended` · `clotho-error` 이벤트가 올라옵니다.

## 딥링크

```ts
import { bindUrlState, shareUrl } from "@kokoa/clotho/dom";

const unbind = bindUrlState(handle.player, doc);
shareUrl(handle.player, doc); // https://…/knapsack?c=swap
```

`/animations/knapsack?c=swap&speed=1.5` 처럼 **특정 순간을 가리키는 링크**를 만듭니다.

시각(`t`)보다 **chapter(`c`)를 권장합니다.** 문서를 고치면 `t=3200`은 조금씩 어긋나지만 chapter id는 저작자가 이름 붙인 그 순간을 계속 가리킵니다.

URL은 **일시정지·seek·속도 변경 같은 조작에만** 기록되고 재생 중에는 건드리지 않습니다. `replaceState`를 쓰므로 뒤로 가기가 애니메이션 히스토리로 채워지지 않습니다.

## 스크롤리텔링

```ts
import { mountScrollPlayer } from "@kokoa/clotho/dom";

mountScrollPlayer(document.querySelector("#stage"), doc, {
  pin: true,            // 구간 동안 stage를 sticky로 고정
  snapToChapters: true, // chapter마다 같은 양의 스크롤을 배분
});
```

긴 글 속의 애니메이션은 대부분 읽히지 않습니다. 재생 버튼을 누르지 않고, 눌러도 자기 읽기 속도와 무관하게 흘러가는 화면을 따라가지 못합니다. 자동 재생은 반대 문제를 만듭니다.

`mountScrollPlayer`는 시계를 스크롤로 갈아끼웁니다. `Player`가 이미 프레임워크 밖에 있고 `seek(t)`가 순수하기 때문에 **되감기가 자유롭습니다** — 위로 스크롤하는 것은 더 작은 숫자이지 되돌리기가 아닙니다.

`prefers-reduced-motion`에서는 스크롤 연동을 끄고 **chapter별 정지 프레임 목록으로 강등합니다.** 스크롤 하이재킹은 전정기관 문제가 있는 독자에게 특히 나쁘고, 속도를 늦추는 것으로는 해결되지 않습니다.

## 발표자 모드

```ts
import { mountPresenter } from "@kokoa/clotho/dom";
mountPresenter(document.body, doc);
```

`→`/`Space` 다음 구간, `←` 이전, `P` 재생/정지, `N` 발표자 노트, `B` 블랙아웃, `F` 전체화면.

chapter가 있는 문서는 이미 슬라이드의 구조를 갖고 있습니다 — 순서가 있고, 각 단계에 제목과 부제가 있고, 넘어가는 지점이 정해져 있습니다. 부족한 것은 **말하는 속도로 넘기는 방법**뿐이었습니다.

chapter를 **구간**으로 다루므로 다음을 누르면 그 구간을 **재생하고 멈춥니다.** chapter 시각으로 점프하지 않습니다 — 애니메이션이 설명의 일부라서 건너뛰면 청중은 과정 없는 결과만 봅니다.

발표자 메모는 `chapters[].notes`에 씁니다. `subtitle`은 **청중이 읽는 자막**이라 겸용할 수 없습니다 — 공유 화면에 나오는 필드가 "내가 무슨 말을 하려 했더라"를 적어두는 자리가 될 수는 없습니다.
